# API 키 회전 후속 실행 계획

## 완료된 항목 (현재 develop 기준)

1. API 키 회전/롤백 API 백엔드 구현 완료
  - `POST /api/keys/:provider/rotate`
  - `POST /api/keys/:provider/rollback`
  - 회전 전/후 힌트와 이전 키 상태 저장
2. DB 마이그레이션 완료
  - `user_api_keys`에 `previous_*` 컬럼 추가
3. 설정 화면 연동 완료
  - 회전 저장 흐름 및 롤백 버튼 추가
4. 회전/롤백 라우트 통합 테스트 추가
  - 성공, 검증 실패, 롤백 복원 케이스

## 바로 다음 단계 (자동 진행 우선순위)

### P0: 운영 안전성 보강

- 연속 실패 감시
  - `rotate` 실패 횟수, 최근 실패 사유, 마지막 성공 시각을 추적
  - 실패가 연속 3회 이상이면 경고 노출
- 롤백 안전성
  - 롤백 요청 실패 시 사용자 메시지 고정 형식 적용
  - 롤백 가능 여부(remaining rollback window) UI 경고

### P1: 운영 가시성 보강

- API 키 경로 메트릭 추가
  - 회전 성공/실패 카운트
  - 프로바이더별 5xx 비율
- Sentry 로그 정규화
  - 회전/롤백 오류에 `provider`, `result`, `reason` 태그 추가

### P2: 사용자 체감 개선

- 설정 페이지 키 힌트 정책 정리
  - 회전 버튼 라벨/툴팁을 "키 회전" 기준으로 고정
- 롤백 안내 텍스트 강화
  - 롤백은 직전 1회 복원만 가능함을 명확히 고지

## 다음 기능 후보 (승인되면 바로 착수)

1. `provider`별 키 분실 복구 보조 기능
  - 회전/삭제된 키에 대한 사용자 셀프 가이드 템플릿 제공
2. 비동기 모델 캐시 만료 정책 고도화
  - 키 갱신 시 실시간 캐시만 무효화하고, 레거시 캐시 잔존 방지
3. API 키 발급 실패 원인별 UI 텍스트 분기
  - `INVALID_KEY`, `SERVICE_UNAVAILABLE`, `UNKNOWN` 메시지 일관화

## 종료 조건

- 위 P0 항목 2개가 모두 동작할 때까지 다음 주요 배포 지연
- 배포 전 체크리스트에서 `013_user_api_keys_rotation` 적용 여부를 강제 점검
